64-bar intro experiment

September 15, 2026 · Film Score Studio

Result: inconclusive comparison; neither workflow completed a verified intro. No saved project or normal application workflow was changed. No complete MIDI candidate was approved or exported.

What was tested

An original cinematic intro, 64 bars in 4/4 at 72 BPM (256 beats, about 3 minutes 33 seconds), extending a synthetic 24-note opening across existing piano, string ensemble, and French horn tracks. Existing material and track membership were preserved.

The final isolated pair used the same xAI model, grok-4.20-0309-non-reasoning, identical score bounds and generous 16,000-token initial response allowances for equivalent advisory/skill and writer stages. The current workflow's adviser allowance was lifted only in the experiment. Normal production behavior was unchanged.

The alternative retained instrument writers and used a consistent Orchestrator identity with progressively loaded style, concept, and verification skill documents, accumulated working context, and private MIDI references dereferenced for the targeted writer. This was a fixed sequence, not an autonomous skill-selection system. Both retained bounded repairs and atomic MIDI validation.

Current: an adviser safety-screen failure recovered. Piano writing then produced a note extending past its region. The bounded musical-regeneration response ended with tool_calls, not an accepted completed JSON response. No candidate was committed.

Consolidated: style, concept, planning, piano, and strings completed. Piano and strings produced six valid staged operations. French horn failed bounded response validation after the initial request and two repairs. The final sanitized error did not retain the field-level diagnosis, so the precise horn defect is unknown. Partial staged work was not promoted to a candidate.

Neither whole-score Orchestrator verification nor blind candidate evaluation could be exercised. Thus there is no evidence here that one approach produces better music or a higher completion rate. The consolidated approach reached more track writing, but also used more cumulative input tokens.

How large did the context get?

The consolidated peak was approximately 11.8 thousand input tokens and 48 KB. All source material and loaded skills were retained; no arbitrary score truncation was used. The experiment did not hit an observed input-context limit, and the provider metadata did not supply a documented maximum context size.

This is not a huge-context stress test: the baseline had only 24 notes, and neither workflow finished the requested 64-bar score. Requested duration alone does not establish context size. The main observed blockers were output correctness and response handling, not input capacity.

At fixed track count and note density, storage and inline context grow roughly with bar count. Sending the entire score to every writer multiplies that cost by the number of calls. Accumulated skill replies and private MIDI add further input. Larger input capacity does not make an arbitrarily large output reliable.

Recommended strategy before scaling

  1. Write bounded sections: ask each instrument agent for 8–16 bars at a time, with explicit local timing and transition constraints. Validate each section and retain it privately; publish only after the requested whole score passes checks.
  2. Keep a global composition plan: an Orchestrator maintains the full form, motifs, harmonic direction, instrumentation, and original acceptance criteria. Section writing must not lose long-range structure.
  3. Retrieve exact musical data when needed: preserve complete original MIDI in storage, index it by track and beat range, and provide exact relevant notes plus neighboring sections. Derived summaries should guide navigation, never replace source events.
  4. Separate local from global verification: deterministic timing, ownership, and schema checks first; section constraints next; whole-score continuity and musical review last.
  5. Make limits score-aware: current validators cap region starts at beat 512, region durations at 128 beats, notes per region at 512, and operations per workflow at 60. Very long scores require deliberate limit/paging changes as well as context strategies.
  6. Measure again on completed larger scores: use multiple paired prompts and dense existing scores after section writing works. Report peak context, cumulative tokens, completion rate, fidelity, and blind musical quality separately.

Experiment limitations and provenance

Two earlier setup attempts were excluded: unequal response budgets stopped the first before composition; the next exposed a missing advisory-MIDI loader and an incomplete experimental writer contract. They remain separate evidence, not architecture results. The final harness passed offline full-flow and negative fixtures before the final live pair; its executed source and directly imported production modules were hashed and verified.

The final experiment remains a single synthetic three-track prompt. It did not finish either candidate, did not establish a maximum feasible score size, and does not justify replacing the normal workflow. The strongest next step is section-based generation with unchanged transactional safety, followed by a broader comparison.
