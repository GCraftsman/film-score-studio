---
name: Provider truncation recovery
description: Lossless bounded recovery differs from structural repair of a complete response.
---

Treat provider token exhaustion or a provider request deadline as an incomplete response, not proof of malformed musical edits. Recovery must request a complete replacement with a larger bounded output budget and retain the full response-producing context, including mediated consultation replies. A timeout has no partial musical response, so its first complete replacement may establish the baseline; a token-limited response may only preserve independently closed operations.

**Why:** Repeating structural-only instructions at the same output limit cannot recover a missing suffix. A syntactically valid response can also report provider truncation and must not be accepted as complete.

**How to apply:** Keep the shared two-repair ceiling and atomic score application. Preserve complete valid edits across attempts, including their multiplicity; never guess partial notes or silently accept a smaller batch. If extracting complete objects from an incomplete envelope, recognize only the root operations array with JSON-aware string and nesting handling. Nested examples are not edits. A token-limited response with no certifiable closed operation fails closed rather than regenerating uncertain music. Keep raw responses private to recovery prompts and log only bounded diagnostics; timeout diagnostics contain no response content.
